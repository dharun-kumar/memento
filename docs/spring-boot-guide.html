1. Build Tools — Gradle Kotlin DSL

Before a single line of Spring Boot can run, you need a build tool. It does two jobs: manage your dependencies (the libraries your project needs) and compile + package your code into a runnable JAR. The two biggest options in the Java ecosystem are Maven (XML config) and Gradle (DSL config). Memento uses Gradle with the Kotlin DSL — more concise, type-safe, and the natural choice for modern Spring Boot projects.

FeatureMaven (pom.xml)Gradle Kotlin DSL (build.gradle.kts)
Config formatXML — verbose but universalKotlin DSL — concise, type-safe, IDE-friendly
Build speedSlower (no incremental builds by default)Faster — incremental builds, build cache
Dependency syntax<dependency>...</dependency>implementation("group:artifact:version")
Best forTraditional enterprise, existing projectsNew projects, multi-module, Android

Here's the complete build.gradle.kts for Memento. Notice the runtimeOnly vs implementation distinction — it keeps unnecessary code off the compile classpath:

💡 runtimeOnly vs implementation implementation — on the compile + runtime classpath (your code uses it directly). runtimeOnly — only needed at runtime, not compile time. The PostgreSQL JDBC driver and JJWT implementation jars are never referenced in source code — they're loaded by reflection at runtime, so runtimeOnly is correct and keeps your compile classpath lean.

2. JDBC — Talking to Databases

JDBC (Java Database Connectivity) is the low-level standard API that connects Java code to relational databases. Every higher-level abstraction — JPA, Hibernate, Spring Data — ultimately calls JDBC under the hood. Understanding JDBC helps you understand what the framework is doing on your behalf.

The four layers in JDBC's architecture: your application code issues commands using JDBC API interfaces (Connection, PreparedStatement, ResultSet). The DriverManager selects the right JDBC Driver (e.g. the PostgreSQL driver from the runtimeOnly dependency above) based on your connection URL, and that driver handles the actual network communication with the database server.

Raw JDBC — what Spring does for you under the hood
Connection conn = DriverManager.getConnection(
    "jdbc:postgresql://localhost:5432/memento", "memento", "memento123"
);

// PreparedStatement prevents SQL injection — always use it over Statement
PreparedStatement stmt = conn.prepareStatement(
    "SELECT * FROM bookmarks WHERE user_id = ?"
);
stmt.setLong(1, userId);

ResultSet rs = stmt.executeQuery();
while (rs.next()) {
    System.out.println(rs.getString("title") + " → " + rs.getString("url"));
}
conn.close(); // must not forget — leaks connections otherwise

This is a lot of boilerplate — connection management, exception handling, resource cleanup. You'd also need a connection pool to avoid opening a new TCP connection per request. Spring Data JPA eliminates all of this. But knowing raw JDBC makes you appreciate why HikariCP (Spring Boot's default pool) matters — we'll revisit that in the production config section.

3. Spring Core — IoC & Dependency Injection

Spring's entire philosophy rests on two ideas: Inversion of Control (IoC) and Dependency Injection (DI). Get these right and the rest of Spring becomes natural.

The problem Spring solves

A real app has layers: BookMarkController needs BookMarkService, which needs BookMarkRepository, which needs a database connection. Without a framework:

Manual wiring — painful at scale
public class BookMarkController {
    private BookMarkService service = new BookMarkService(); // tight coupling
}
public class BookMarkService {
    private BookMarkRepository repo = new BookMarkRepository(); // can't test in isolation
}

Every new keyword tightly couples the classes. You can't swap BookMarkRepository for a mock in tests. And managing when to create or destroy objects across a large app becomes unmanageable.

IoC (Inversion of Control) is the principle: give up control of object creation to the framework. You say "here is what I need"; Spring figures out how to build and wire it. IoC is just a principle — the mechanism that implements it in Java is Dependency Injection.

DI means an object receives its dependencies from outside rather than creating them itself. Spring's IoC container creates all your objects (called Beans), stores them, and injects them wherever they're needed.

📘 Key Terms Bean — any object managed by Spring's IoC container.
IoC Container — the part of Spring that creates, stores, and wires beans.
DI — the mechanism: Spring injects a bean into another bean's constructor, setter, or field.

4. Three Ways to Do Dependency Injection

Spring supports three DI styles. Memento uses constructor injection throughout — here's why that's the right call, and what the alternatives look like.

Field Injection — convenient but discouraged

Field Injection
@RestController
public class BookMarkController {

    @Autowired
    private BookMarkService service; // Spring injects directly into the field

    @GetMapping("/api/bookmarks")
    public List<BookMark> getAll() { return service.getAllBookmarks(); }
}
⚠️ Why field injection is discouraged Hidden dependencies — you can't see what a class needs without reading all its fields. Can't be final. Impossible to test without Spring (no way to pass a mock without reflection hacks). Spring itself recommends against it for production code.

Setter Injection — for optional dependencies

Setter Injection
@RestController
public class BookMarkController {

    private BookMarkService service;

    @Autowired
    public void setService(BookMarkService service) {
        this.service = service;
    }
}

Constructor Injection ✅ — the right choice

Constructor Injection — used throughout Memento
@RestController
public class BookMarkController {

    private final BookMarkService service; // final — immutable once wired

    // Single constructor: @Autowired not needed in Spring Boot 2+
    public BookMarkController(BookMarkService service) {
        this.service = service;
    }
}
✅ Why constructor injection wins Dependencies are explicit (visible in the constructor signature). Field can be final. Easy unit testing — just pass a mock directly. Spring detects circular dependencies at startup instead of at runtime. Memento uses this pattern in every class.

Resolving ambiguity — @Primary and @Qualifier

If two classes implement the same interface and both are @Component, Spring throws an error on startup — it doesn't know which to inject. Two fixes:

Fix 1 — @Primary
@Component
@Primary // preferred when both exist
public class LaptopService
    implements ComputerService {}

@Component
public class DesktopService
    implements ComputerService {}
Fix 2 — @Qualifier
public MyController(
  @Qualifier("desktopService")
  ComputerService computerService
) {
  this.computerService = computerService;
}

5. Spring Boot — The Simplified Framework

Plain Spring requires a mountain of configuration — XML, manual bean wiring, application server setup. Spring Boot is an opinionated layer on top that gives you sensible defaults, auto-configuration, and an embedded server, letting you go from zero to running app in minutes.

JAR vs WAR

WAR (traditional)JAR (Spring Boot)
ServerExternal Tomcat — install separatelyEmbedded Tomcat — ships inside the JAR
RunCopy WAR into webapps/, start Tomcatjava -jar memento.jar
Config overheadHigh — XML descriptors, server configMinimal — application.properties
ContainerRuns in server's JVMRuns in its own JVM — ideal for Docker
MementoApplication.java
package com.memento;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cache.annotation.EnableCaching;

@SpringBootApplication  // = @Configuration + @EnableAutoConfiguration + @ComponentScan
@EnableCaching          // activates Spring's caching abstraction (Section 14)
public class MementoApplication {
    public static void main(String[] args) {
        SpringApplication.run(MementoApplication.class, args);
        // Starts IoC container + embedded Tomcat
        // Flyway migrations run, beans are wired, server starts on port 8080
    }
}

6. IoC Container & ApplicationContext

When SpringApplication.run() is called, Spring scans your project for annotated classes and creates a bean for each one. The stereotype annotations tell Spring what role each class plays — they're all specialisations of @Component:

@Component — generic managed bean @Service — business logic (BookMarkService) @Repository — data access (BookMarkRepository) @Controller — MVC views (AuthController) @RestController — REST API (BookMarkController) @Configuration — config beans (SecurityConfig)

The @Repository annotation does one extra thing beyond @Component: it makes Spring translate database exceptions (like SQLException) into Spring's own DataAccessException hierarchy. This is useful — your service layer doesn't need to know which database you're using.

Fetching beans programmatically (debugging tool)
@SpringBootApplication
@EnableCaching
public class MementoApplication {
    public static void main(String[] args) {
        // run() returns the ApplicationContext — the live IoC container
        ApplicationContext ctx = SpringApplication.run(MementoApplication.class, args);

        // Fetch by type — no cast needed, Spring knows the exact type
        BookMarkService svc = ctx.getBean(BookMarkService.class);
    }
}

In practice you'll never call getBean() in real code — Spring handles all wiring via constructor injection. This is purely a debugging/exploration tool.

7. Spring Boot Web — Building REST APIs

Spring MVC sits at the core of Spring Boot's web layer. Every incoming HTTP request passes through a DispatcherServlet (Spring's front controller), which routes it to the right method based on URL + HTTP verb mappings.

AnnotationPurpose
@RestController= @Controller + @ResponseBody. All methods return data (JSON by default), not view names.
@RequestMappingSets base URL path for all methods in the class.
@GetMapping / @PostMapping / @PutMapping / @DeleteMappingMap specific HTTP verbs to methods.
@PathVariableExtracts a segment from the URL: /bookmarks/{title}.
@RequestBodyDeserialises the JSON request body into a Java object.
@ValidTriggers Bean Validation on the incoming object before the method runs.
Memento — BookMarkController.java
controller/BookMarkController.java
@RestController
@RequestMapping("/api/bookmarks")
public class BookMarkController {

    private final BookMarkService service;

    public BookMarkController(BookMarkService service) {
        this.service = service;
    }

    // GET /api/bookmarks — list all bookmarks for the logged-in user
    @GetMapping
    public ResponseEntity<List<BookMark>> getAllBookmarks() {
        return ResponseEntity.ok(service.getAllBookmarks());
    }

    // POST /api/bookmarks — add a new bookmark (@Valid triggers Bean Validation)
    @PostMapping
    public ResponseEntity<BookMark> addBookmark(@Valid @RequestBody BookMark bookMark) {
        return ResponseEntity.status(HttpStatus.CREATED)
                            .body(service.addBookmark(bookMark));
    }

    // DELETE /api/bookmarks/{title}
    @DeleteMapping("/{title}")
    public ResponseEntity<Void> deleteBookmark(@PathVariable String title) {
        service.deleteBookmark(title);
        return ResponseEntity.noContent().build();
    }

    // PUT /api/bookmarks/{title} — update a bookmark
    @PutMapping("/{title}")
    public ResponseEntity<BookMark> updateBookmark(
            @PathVariable String title,
            @Valid @RequestBody BookMark bookMark) {
        return ResponseEntity.ok(service.updateBookmark(title, bookMark));
    }
}

8. JPA & Hibernate — Persisting Data

JPA (Java Persistence API) is a standard that maps Java classes to database tables so you work with objects rather than SQL. Hibernate is the most popular JPA implementation — it generates the SQL. Spring Data JPA wraps Hibernate and auto-generates repository code so you barely write any SQL at all.

The Bookmark entity

Memento's BookMark entity has a few interesting design decisions: title is the primary key (a natural key instead of a generated ID), userId is hidden from API responses with @JsonIgnore, and Bean Validation annotations guard fields at the HTTP layer.

Memento — model/BookMark.java
model/BookMark.java
import jakarta.persistence.*;
import jakarta.validation.constraints.*;
import com.fasterxml.jackson.annotation.JsonIgnore;

@Entity  // maps this class to the "book_mark" table (Flyway creates it)
public class BookMark {

    @Id  // title is the natural primary key — no auto-increment needed
    @NotBlank(message = "Title cannot be blank")
    @Size(max = 255, message = "Title must be 255 chars or fewer")
    private String title;

    @NotBlank(message = "URL cannot be blank")
    @Size(max = 2048)
    private String url;

    @JsonIgnore  // never exposed in API responses — internal ownership field
    private Long userId;

    // getters and setters...
}
📘 Natural key vs generated ID Using title as @Id means every bookmark title must be unique per user. The tradeoff: simpler API URLs (/api/bookmarks/My+Article) but updates that change the title require delete + re-insert. For Memento's use case — an AI agent managing bookmarks by name — this is a deliberate and sensible choice.

The User entity

Memento — model/User.java
model/User.java
@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY) // maps to BIGSERIAL in Postgres
    private Long id;

    @Column(unique = true, nullable = false)
    private String username;

    private String password; // BCrypt-hashed, never plaintext

    @Enumerated(EnumType.STRING) // stores "ADMIN" not "0" — safe to reorder enum values
    private Role role;
}

The Repository

repository/BookMarkRepository.java

    // Spring Data generates SQL from the method name — no @Query needed

    void deleteByTitleAndUserId(String title, Long userId);
}

9. Flyway — Database Migrations

A common Spring Boot gotcha: new developers reach for spring.jpa.hibernate.ddl-auto=create which auto-generates tables. This is fine for learning, but dangerous in production — it can drop and recreate your tables on startup, destroying data. Flyway is the proper answer: versioned SQL scripts that run exactly once, in order, and are tracked in a flyway_schema_history table.

Memento sets spring.jpa.hibernate.ddl-auto=none — Hibernate never touches the schema. Flyway owns it entirely.

Memento — V1__init.sql
src/main/resources/db/migration/V1__init.sql
-- users table with BIGSERIAL PK and BCrypt password
CREATE TABLE users (
    id       BIGSERIAL PRIMARY KEY,
    username VARCHAR(255) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    role     VARCHAR(50)  NOT NULL CHECK (role IN ('USER', 'ADMIN'))
);

-- bookmarks table: composite PK on (title, user_id)
-- CASCADE DELETE: removing a user removes all their bookmarks
CREATE TABLE book_mark (
    title   VARCHAR(255) NOT NULL,
    url     VARCHAR(2048) NOT NULL,
    user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    PRIMARY KEY (title, user_id)
);
src/main/resources/db/migration/V2__seed_admin.sql
-- ON CONFLICT DO NOTHING makes this idempotent —
-- safe to run multiple times without error
INSERT INTO users (username, password, role)
VALUES (
    'admin',
    '$2a$12$...', -- BCrypt hash of the initial admin password
    'ADMIN'
)
ON CONFLICT (username) DO NOTHING;
🐛 Spring Boot 4.x gotcha — Flyway silent skip Adding flyway-database-postgresql to your dependencies causes FlywayAutoConfiguration to silently do nothing. Fix: set spring.flyway.enabled=false and create an explicit @Bean instead:
config/FlywayConfig.java — explicit bean bypasses broken auto-config
@Configuration
public class FlywayConfig {

    @Bean(initMethod = "migrate")  // runs migrate() on startup
    public Flyway flyway(DataSource dataSource) {
        return Flyway.configure()
            .dataSource(dataSource)
            .locations("classpath:db/migration")
            .load();
    }
}

10. Spring Security — Dual Auth (JWT + Session)

Memento needs two auth mechanisms on the same app: a browser user who logs in with a form (session-based), and an AI agent that uses a JWT token (stateless). Spring Security supports this cleanly through multiple SecurityFilterChain beans ordered with @Order.

Every HTTP request passes through Spring's filter chain before reaching your controllers. Spring evaluates chains in order and uses the first one whose matcher matches the request path.

Memento — config/SecurityConfig.java
config/SecurityConfig.java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    private final JwtAuthFilter jwtAuthFilter;
    private final CustomUserDetailsService userDetailsService;

    public SecurityConfig(JwtAuthFilter jwtAuthFilter,
                          CustomUserDetailsService userDetailsService) {
        this.jwtAuthFilter = jwtAuthFilter;
        this.userDetailsService = userDetailsService;
    }

    // ── Chain 1: JWT for /api/** ──────────────────────────────
    @Bean
    @Order(1)
    public SecurityFilterChain apiFilterChain(HttpSecurity http) throws Exception {
        return http
            .securityMatcher("/api/**")         // only intercepts /api/** paths
            .csrf(c -> c.disable())              // no CSRF for stateless REST
            .authorizeHttpRequests(a -> a
                .anyRequest().authenticated())
            .sessionManagement(s -> s
                .sessionCreationPolicy(SessionCreationPolicy.NEVER)) // never create sessions
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }

    // ── Chain 2: Form login for browser ──────────────────────
    @Bean
    @Order(2)
    public SecurityFilterChain webFilterChain(HttpSecurity http) throws Exception {
        return http
            .authorizeHttpRequests(a -> a
                .requestMatchers("/login", "/register").permitAll()
                .anyRequest().authenticated())
            .formLogin(f -> f
                .loginPage("/login").defaultSuccessUrl("/token", true))
            .logout(l -> l
                .logoutRequestMatcher(req ->      // AntPathRequestMatcher removed in Sec 7.x
                    "GET".equals(req.getMethod()) && "/logout".equals(req.getRequestURI()))
                .logoutSuccessUrl("/login?logout"))
            .build();
    }

    // ── Completely bypass chains for static assets ───────────
    @Bean
    public WebSecurityCustomizer webSecurityCustomizer() {
        // MVC matchers silently fail for paths with no @Controller mapping in Sec 7.x
        // → Use web.ignoring() instead of permitAll() for WebJars/Swagger/static
        return web -> web.ignoring().requestMatchers(
            "/webjars/**", "/swagger-ui/**", "/v3/api-docs/**"
        );
    }

    @Bean
    public AuthenticationProvider authenticationProvider() {
        var provider = new DaoAuthenticationProvider();
        provider.setUserDetailsService(userDetailsService);
        provider.setPasswordEncoder(new BCryptPasswordEncoder(12));
        return provider;
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(12);
    }
}
📘 Why two chains instead of one? A single chain can only have one session policy. JWT auth needs NEVER (no sessions at all); form login needs sessions to keep the user logged in between page loads. Two chains with @Order let each path get the policy it needs — /api/** gets stateless JWT, everything else gets session-based form login.

11. Custom JWT Filter

For /api/** requests, the JWT filter intercepts every request, validates the Bearer token, and populates Spring's SecurityContext so downstream code knows who the caller is.

Memento — filter/JwtAuthFilter.java
filter/JwtAuthFilter.java
@Component  // registered as a bean
public class JwtAuthFilter extends OncePerRequestFilter {
    // OncePerRequestFilter guarantees exactly one execution per request,
    // even across internal forwards/includes

    private final JwtUtil jwtUtil;
    private final CustomUserDetailsService userDetailsService;

    public JwtAuthFilter(JwtUtil jwtUtil, CustomUserDetailsService uds) {
        this.jwtUtil = jwtUtil;
        this.userDetailsService = uds;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                      HttpServletResponse response,
                                      FilterChain chain)
            throws ServletException, IOException {

        String header = request.getHeader("Authorization");

        if (header == null || !header.startsWith("Bearer ")) {
            chain.doFilter(request, response); // no token → pass through
            return;
        }

        String token = header.substring(7); // strip "Bearer " prefix
        String username = jwtUtil.extractUsername(token);

        if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {
            UserDetails userDetails = userDetailsService.loadUserByUsername(username);

            if (jwtUtil.isTokenValid(token, userDetails)) {
                // Create auth token and put it in the SecurityContext
                var authToken = new UsernamePasswordAuthenticationToken(
                    userDetails, null, userDetails.getAuthorities()
                );
                authToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }
        chain.doFilter(request, response);
    }
}

// ── CRITICAL: prevent double-registration ──────────────────────────
// Spring Boot auto-registers ALL @Component beans that are Filters as
// global servlet filters. JwtAuthFilter is also added manually inside
// the security chain → it would run TWICE without this.
@Bean
public FilterRegistrationBean<JwtAuthFilter> jwtFilterRegistration(JwtAuthFilter filter) {
    var reg = new FilterRegistrationBean<>(filter);
    reg.setEnabled(false); // disable global auto-registration
    return reg;
}

12. UserDetails & UserDetailsService

Spring Security works with its own UserDetails interface — it doesn't know about your User entity directly. You create a wrapper class that adapts your entity to what Spring expects. This cleanly separates your persistence layer from your security layer.

Memento — config/AppUserDetails.java
config/AppUserDetails.java
public class AppUserDetails implements UserDetails {

    private final User user;

    public AppUserDetails(User user) { this.user = user; }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        // ROLE_ prefix convention: enum stores "ADMIN", Spring needs "ROLE_ADMIN"
        return List.of(new SimpleGrantedAuthority("ROLE_" + user.getRole().name()));
    }

    @Override public String getPassword()               { return user.getPassword(); }
    @Override public String getUsername()               { return user.getUsername(); }

    // All four lifecycle methods must be explicitly implemented — no defaults
    @Override public boolean isAccountNonExpired()   { return true; }
    @Override public boolean isAccountNonLocked()    { return true; }
    @Override public boolean isCredentialsNonExpired() { return true; }
    @Override public boolean isEnabled()              { return true; }

    public Long getUserId() { return user.getId(); } // helper for service layer
}

// ── UserDetailsService — called by Spring during form login ────────
@Service
public class CustomUserDetailsService implements UserDetailsService {

    private final UserRepository userRepository;

    public CustomUserDetailsService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        User user = userRepository.findByUsername(username)
            .orElseThrow(() -> new UsernameNotFoundException("User not found: " + username));
        return new AppUserDetails(user);
    }
}

13. JWT with JJWT 0.12.6

A JWT (JSON Web Token) is a compact, signed string — three Base64-encoded parts separated by dots: header.payload.signature. The signature is what makes it trustworthy: only the server that holds the secret key can produce a valid one.

Memento — config/JwtUtil.java
config/JwtUtil.java
@Component
public class JwtUtil {

    @Value("${app.jwt.secret}")
    private String secretString;

    @Value("${app.jwt.expiration-ms}")
    private long expirationMs;

    private SecretKey signingKey;

    @PostConstruct
    // Runs once after the bean is created — caches the key so we don't
    // re-derive it on every request. Base64 decode + HMAC derivation is
    // cryptographic work — doing it per request is wasteful.
    public void init() {
        byte[] keyBytes = Decoders.BASE64.decode(secretString);
        this.signingKey = Keys.hmacShaKeyFor(keyBytes);
    }

    public String generateToken(AppUserDetails userDetails) {
        return Jwts.builder()
            .subject(userDetails.getUsername())
            .claim("userId", userDetails.getUserId())
            .claim("role",   userDetails.getAuthorities().iterator().next().getAuthority())
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + expirationMs))
            .signWith(signingKey)
            .compact();
    }

    public String extractUsername(String token) {
        return parseClaims(token).getSubject();
    }

    public boolean isTokenValid(String token, UserDetails userDetails) {
        return extractUsername(token).equals(userDetails.getUsername())
            && !isTokenExpired(token);
    }

    private Claims parseClaims(String token) {
        return Jwts.parser()
            .verifyWith(signingKey)
            .build()
            .parseSignedClaims(token)  // throws if signature invalid or expired
            .getPayload();
    }

    private boolean isTokenExpired(String token) {
        return parseClaims(token).getExpiration().before(new Date());
    }
}

14. Caching with Spring Cache + Caffeine

Every time an AI agent calls GET /api/bookmarks — which can happen frequently — without caching you'd hit the database every single time. Spring's caching abstraction with Caffeine (an in-process cache) solves this elegantly using annotations.

Memento — service/BookMarkService.java
service/BookMarkService.java
@Service
public class BookMarkService {

    private final BookMarkRepository bookMarkRepository;
    private final UserRepository userRepository;

    // Returns the ID of the currently authenticated user from SecurityContext
    // Must be public — Spring's SpEL calls it via reflection in cache key expressions
    public Long currentUserId() {
        var auth = (AppUserDetails) SecurityContextHolder.getContext()
                        .getAuthentication().getPrincipal();
        return auth.getUserId();
    }

    // Cache key is per-user: "all:42", "all:7", etc.
    // Result is served from cache on repeat calls — no DB query
    @Cacheable(value = "bookmarks", key = "'all:' + #root.target.currentUserId()")
    public List<BookMark> getAllBookmarks() {
        return bookMarkRepository.findByUserId(currentUserId());
    }

    // After any write, clear the entire cache so next read is fresh
    @CacheEvict(value = "bookmarks", allEntries = true)
    public BookMark addBookmark(BookMark bookMark) {
        if (bookMarkRepository.existsByTitleAndUserId(bookMark.getTitle(), currentUserId()))
            throw new BookMarkExistException(bookMark.getTitle());
        bookMark.setUserId(currentUserId());
        return bookMarkRepository.save(bookMark);
    }

    @CacheEvict(value = "bookmarks", allEntries = true)
    public void deleteBookmark(String title) {
        if (!bookMarkRepository.existsByTitleAndUserId(title, currentUserId()))
            throw new BookMarkNotFoundException(title);
        bookMarkRepository.deleteByTitleAndUserId(title, currentUserId());
    }
}

The cache is configured in application.properties:

application.properties — cache config

# max 500 entries, each expires 10 minutes after being written

15. Bean Validation & Global Exception Handling

Bean Validation (JSR-380) lets you put constraint annotations directly on your model fields. When @Valid appears on a @RequestBody parameter, Spring runs all constraints before the method executes. If any fail, it throws MethodArgumentNotValidException — which you catch centrally.

Memento — exception/GlobalExceptionHandler.java
exception/GlobalExceptionHandler.java
@RestControllerAdvice  // = @ControllerAdvice + @ResponseBody
public class GlobalExceptionHandler {

    // 404 — bookmark not found
    @ExceptionHandler(BookMarkNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public Map<String, String> handleNotFound(BookMarkNotFoundException ex) {
        return Map.of("error", ex.getMessage());
    }

    // 409 — bookmark title already exists for this user
    @ExceptionHandler(BookMarkExistException.class)
    @ResponseStatus(HttpStatus.CONFLICT)
    public Map<String, String> handleConflict(BookMarkExistException ex) {
        return Map.of("error", ex.getMessage());
    }

    // 400 — @Valid constraint violations, with field-level error map
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Map<String, String> handleValidation(MethodArgumentNotValidException ex) {
        return ex.getBindingResult().getFieldErrors().stream()
            .collect(Collectors.toMap(
                FieldError::getField,
                e -> e.getDefaultMessage() != null ? e.getDefaultMessage() : "Invalid"
            ));
    }

    // 404 — missing static resources (without this, falls through to 500)
    @ExceptionHandler(NoResourceFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public Map<String, String> handleNoResource(NoResourceFoundException ex) {
        return Map.of("error", "Resource not found");
    }

    // 500 — catch-all for anything unexpected
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public Map<String, String> handleGeneric(Exception ex) {
        return Map.of("error", "Internal server error");
    }
}

16. Rate Limiting with Bucket4j

The app is accessible to AI agents that can fire requests rapidly. Without rate limiting, a runaway agent or a bad actor could hammer the API. Memento uses Bucket4j's token bucket algorithm — each IP gets a bucket of tokens; each request consumes one; tokens refill over time.

Memento — filter/RateLimitFilter.java
filter/RateLimitFilter.java
@Component
@Order(Ordered.HIGHEST_PRECEDENCE) // runs before security chain
public class RateLimitFilter extends OncePerRequestFilter {

    @Value("${app.rate-limit.capacity}")
    private int capacity;

    @Value("${app.rate-limit.refill-per-minute}")
    private int refillPerMinute;

    // One bucket per IP, created lazily — no pre-allocation needed
    private final ConcurrentHashMap<String, Bucket> buckets = new ConcurrentHashMap<>();

    private Bucket bucketFor(String ip) {
        return buckets.computeIfAbsent(ip, k -> Bucket.builder()
            .addLimit(Bandwidth.builder()
                .capacity(capacity)
                // Greedy refill: tokens added continuously over the minute,
                // not all at once — smooths burst abuse at refill boundaries
                .refillGreedy(refillPerMinute, Duration.ofMinutes(1))
                .build())
            .build());
    }

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res,
                                      FilterChain chain) throws ServletException, IOException {
        // Skip rate limiting for Swagger/WebJar static assets (~7 requests per page load)
        String path = req.getRequestURI();
        if (path.startsWith("/swagger-ui/") || path.startsWith("/webjars/")
                || path.startsWith("/v3/api-docs")) {
            chain.doFilter(req, res);
            return;
        }

        String ip = req.getRemoteAddr();
        if (!bucketFor(ip).tryConsume(1)) {
            res.setStatus(429); // 429 Too Many Requests
            res.setContentType("application/json");
            res.getWriter().write("{\"error\":\"Too many requests. Please slow down.\"}");
            return;
        }
        chain.doFilter(req, res);
    }
}
application.properties — rate limit config
app.rate-limit.capacity=15         # bucket size: max 15 tokens
app.rate-limit.refill-per-minute=15 # refill rate: 15 tokens/minute

17. Thymeleaf — Server-Side Views

The browser-facing part of Memento uses Thymeleaf, Spring Boot's default server-side templating engine. Unlike @RestController which returns JSON, a @Controller returns view names that Thymeleaf resolves to HTML templates in src/main/resources/templates/.

19. Deployment — Docker + GitHub Actions

Memento is deployed to an Oracle Free Tier VPS (1 GB AMD) using a multi-stage Docker build pushed to GitHub Container Registry, then pulled and started on the VPS via SSH in a GitHub Actions workflow.

Multi-stage Dockerfile

Dockerfile
# Stage 1 — Build with full JDK 25
FROM eclipse-temurin:25-jdk AS builder
WORKDIR /app
COPY . .
RUN ./gradlew bootJar --no-daemon

# Stage 2 — Run with slim JRE 25 Alpine (much smaller image)
FROM eclipse-temurin:25-jre-alpine
WORKDIR /app
COPY --from=builder /app/build/libs/*.jar app.jar
# Cap heap at 350 MB, reduce thread stack to 256 KB — fits in 512 MB container
ENV JAVA_TOOL_OPTIONS="-Xmx350m -Xss256k"
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

GitHub Actions CI/CD

.github/workflows/deploy.yml
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # Log in to GitHub Container Registry (ghcr.io)
      # GITHUB_TOKEN is auto-provided — no PAT needed for same-repo packages
      - name: Log in to ghcr.io
        run: echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io -u "${{ github.actor }}" --password-stdin

      - name: Build and push image
        run: |
          docker build -t ghcr.io/${{ github.repository }}:latest .
          docker push ghcr.io/${{ github.repository }}:latest

      - name: Deploy to VPS
        run: |
          # Copy compose file then SSH to pull and restart only the app container
          # DB container is never restarted — avoids data loss from accidental recreation
          scp docker-compose.yml user@vps:/opt/memento/
          ssh user@vps "cd /opt/memento && docker compose pull app && docker compose up -d app"
