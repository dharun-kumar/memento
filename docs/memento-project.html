1. Project Overview & Auth Flow

Memento is a bookmark manager designed for AI agents. The idea: a user logs in with their browser, lands on a token page, copies their JWT, and hands it to their AI agent. The agent then hits the REST API using that token. Two completely separate auth worlds coexist in the same app.

Spring Boot 4.0.5 Java 25 Gradle (Java DSL) Spring Security 7.x JJWT 0.12.6 Spring Data JPA Flyway Caffeine Cache Bucket4j 8.10.1 Thymeleaf + WebJars springdoc-openapi 2.8.8 PostgreSQL 17 Docker GitHub Actions Oracle VPS (1 GB)

Auth Flow

Browser user opens /login → submits credentials → Spring Security validates via CustomUserDetailsService
2
On success, session is created and user is redirected to /auth/token
3
AuthController.getToken() generates a signed JWT containing userId, username, and role — renders it on the token.html page
4
User copies the JWT and gives it to their AI agent
5
AI agent sends Authorization: Bearer <token> on every request to /api/bookmarks/**

3. Dual SecurityFilterChain

The entire security configuration lives in one class. Two filter chains handle two different worlds. The FilterRegistrationBean that prevents double-registration is also declared here, keeping all security wiring in one place.

⚠ Spring Security 7.x — WebSecurityCustomizer for Static Paths Using .requestMatchers("/webjars/**") inside a filter chain throws an exception in Security 7.x because MVC-based matchers require a matching @Controller — and static assets have none. The fix is WebSecurityCustomizer.ignoring(), which bypasses all filter chains before any matcher runs.
SecurityConfig.java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    private final JwtAuthFilter jwtAuthFilter;

    public SecurityConfig(JwtAuthFilter jwtAuthFilter) {
        this.jwtAuthFilter = jwtAuthFilter;
    }

    // Bypass filter chains entirely for static / doc paths.
    // More reliable than permitAll() inside a chain — paths with no @Controller
    // mapping (like /webjars/**) cause MVC matcher failures in Security 7.x.
    @Bean
    public WebSecurityCustomizer webSecurityCustomizer() {
        return web -> web.ignoring()
            .requestMatchers("/webjars/**")      // Bootstrap CSS/JS from JAR
            .requestMatchers("/swagger-ui/**")    // Swagger UI static files
            .requestMatchers("/v3/api-docs/**");  // OpenAPI JSON spec
    }

    // JwtAuthFilter is @Component so Spring can inject it above.
    // But @Component also causes Boot to auto-register it as a global servlet filter,
    // running it on every path including /login. enabled=false prevents that.
    // The filter is still used — added manually inside jwtFilterChain below.
    @Bean
    public FilterRegistrationBean<JwtAuthFilter> jwtFilterRegistration(JwtAuthFilter filter) {
        FilterRegistrationBean<JwtAuthFilter> reg = new FilterRegistrationBean<>(filter);
        reg.setEnabled(false);
        return reg;
    }

    // ── Chain 1: JWT — /api/** ─────────────────────────────────────────────────
    // Handles only /api/** requests. @Order(1) means it's evaluated first.
    //
    // Two types of callers:
    //   • AI agents  → send Bearer token (JWT auth, fully stateless)
    //   • Browser    → already have a session; NEVER means reuse it, don't create a new one
    // Unauthenticated hits on /api/** redirect to /login (not a 401 JSON error).
    @Bean
    @Order(1)
    public SecurityFilterChain jwtFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/api/**")
            .csrf(csrf -> csrf.disable())
            .sessionManagement(sm -> sm
                .sessionCreationPolicy(SessionCreationPolicy.NEVER)) // reuse session, never create
            .authorizeHttpRequests(auth -> auth
                .anyRequest().authenticated())
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint((req, res, e) ->
                    res.sendRedirect("/login")))  // browser users → login page
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    // ── Chain 2: Session — catch-all ──────────────────────────────────────────
    // No securityMatcher — handles everything not claimed by Chain 1.
    // formLogin configures /login as our login page and handles POST /login automatically.
    @Bean
    @Order(2)
    public SecurityFilterChain sessionFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())  // logout uses GET link, no CSRF token needed
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/**").permitAll()
                .requestMatchers("/login").permitAll()
                .anyRequest().authenticated())
            .formLogin(form -> form
                .loginPage("/login")
                .defaultSuccessUrl("/auth/token", true) // → token display page after login
                .permitAll())
            .logout(logout -> logout
                // logoutRequestMatcher accepts a lambda — AntPathRequestMatcher was removed
                .logoutRequestMatcher(req ->
                    "GET".equals(req.getMethod()) && "/logout".equals(req.getRequestURI()))
                .logoutSuccessUrl("/login?logout")
                .permitAll());
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
ℹ SessionCreationPolicy.NEVER vs STATELESS STATELESS means the chain never reads or creates a session — period. NEVER means it won't create a new session, but it will reuse an existing one if present. Memento uses NEVER so that a browser user who is already logged in can also hit /api/** without needing a token.

4. JwtAuthFilter & FilterRegistrationBean

The filter reads the Authorization header, validates the token with JwtUtil.isValid(), parses the claims, loads the user from DB, and sets the SecurityContext. OncePerRequestFilter guarantees it runs exactly once per request.

🚨 The Double-Registration Trap @Component on a filter causes Spring Boot to register it globally as a servlet filter AND Spring Security adds it inside the chain — so it runs twice. The FilterRegistrationBean(enabled=false) in SecurityConfig prevents the global registration while keeping the bean injectable.
JwtAuthFilter.java
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    private final JwtUtil jwtUtil;
    private final CustomUserDetailsService userDetailsService;

    public JwtAuthFilter(JwtUtil jwtUtil, CustomUserDetailsService userDetailsService) {
        this.jwtUtil = jwtUtil;
        this.userDetailsService = userDetailsService;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                        HttpServletResponse response,
                                        FilterChain filterChain)
            throws ServletException, IOException {

        String header = request.getHeader("Authorization");

        // No Bearer token — skip JWT logic, let Spring Security decide
        if (header == null || !header.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        String token = header.substring(7); // strip "Bearer " prefix

        if (jwtUtil.isValid(token)) {
            Claims claims = jwtUtil.parse(token);
            String username = claims.getSubject();

            UserDetails userDetails = userDetailsService.loadUserByUsername(username);

            // Set the authenticated principal in SecurityContext
            UsernamePasswordAuthenticationToken auth =
                new UsernamePasswordAuthenticationToken(
                    userDetails, null, userDetails.getAuthorities());
            SecurityContextHolder.getContext().setAuthentication(auth);
        }

        filterChain.doFilter(request, response);
    }
}

5. AppUserDetails & CustomUserDetailsService

AppUserDetails copies fields out of the User entity rather than holding a reference to it — this decouples the security layer from the persistence layer. The ROLE_ prefix is added only in getAuthorities(); the Role enum stores clean names (ADMIN, OPERATOR, GUEST).

AppUserDetails.java
public class AppUserDetails implements UserDetails {

    private final Long id;
    private final String username;
    private final String password;
    private final Role role;

    public AppUserDetails(User user) {
        this.id       = user.getId();
        this.username = user.getUsername();
        this.password = user.getPassword();
        this.role     = user.getRole();
    }

    public Long   getId()   { return id; }
    public Role   getRole() { return role; }

    @Override public String getUsername() { return username; }
    @Override public String getPassword() { return password; }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        // hasRole("ADMIN") checks for "ROLE_ADMIN" — prefix added only here
        return List.of(new SimpleGrantedAuthority("ROLE_" + role.name()));
    }

    // All four lifecycle booleans must be explicit — returning null causes auth failures
    @Override public boolean isAccountNonExpired()    { return true; }
    @Override public boolean isAccountNonLocked()     { return true; }
    @Override public boolean isCredentialsNonExpired() { return true; }
    @Override public boolean isEnabled()              { return true; }
}
CustomUserDetailsService.java
@Service
public class CustomUserDetailsService implements UserDetailsService {

    private final UserRepo userRepo;

    public CustomUserDetailsService(UserRepo userRepo) {
        this.userRepo = userRepo;
    }

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        return userRepo.findByUsername(username)
            .map(AppUserDetails::new)
            .orElseThrow(() -> new UsernameNotFoundException("User not found: " + username));
    }
}

6. JwtUtil — Token Generation & Parsing

The token carries three claims: userId, username (as subject), and role. The SecretKey is derived once at startup in @PostConstruct and cached — Base64 decoding and HMAC key derivation are expensive and the key never changes at runtime.

⚠ JJWT 0.12.x API — What Changed Old (0.11.x): Jwts.parserBuilder(), parseClaimsJws(), .setSubject().
New (0.12.x): Jwts.parser(), parseSignedClaims(), .subject(). Using the old API causes NoSuchMethodError at runtime.
JwtUtil.java
@Component
public class JwtUtil {

    @Value("${app.jwt.secret}")
    private String secret;

    @Value("${app.jwt.expiration-ms}")
    private long expirationMs;

    // Derived once at startup — never changes, no need to recompute per request
    private SecretKey signingKey;

    @PostConstruct
    private void init() {
        signingKey = Keys.hmacShaKeyFor(Decoders.BASE64.decode(secret));
    }

    // Token contains userId + role so the caller can read them from claims
    // without an extra DB lookup
    public String generate(Long userId, String username, Role role) {
        return Jwts.builder()
            .subject(username)
            .claim("userId", userId)
            .claim("role", role)
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + expirationMs))
            .signWith(signingKey)
            .compact();
    }

    // Parse and verify signature — throws JwtException if tampered/expired
    public Claims parse(String token) {
        return Jwts.parser()
            .verifyWith(signingKey)
            .build()
            .parseSignedClaims(token)
            .getPayload();
    }

    // Returns false instead of throwing — used in JwtAuthFilter
    public boolean isValid(String token) {
        try { parse(token); return true; }
        catch (JwtException e) { return false; }
    }
}

7. Entities — BookMark, User & Role

BookMark Entity

The bookmark's title is the natural primary key. The bookmark also has a description and an optional tag for filtering. userId is hidden from JSON responses with @JsonIgnore — it's always set by the service from the JWT, never from the client.

ℹ Composite Primary Key in the DB The Java entity uses title as @Id, but the actual SQL table uses a composite primary key (title, user_id). This allows different users to have bookmarks with the same title. The uniqueness constraint is enforced at the DB level; the service also checks existsByTitleAndUserId() before saving.
BookMark.java
@Entity
@Table(name = "bookmarks")
public class BookMark {

    @Id
    @NotBlank(message = "Title must not be blank")
    @Size(max = 255, message = "Title must not exceed 255 characters")
    @Column(nullable = false, length = 255)
    private String title;

    @NotBlank(message = "Description must not be blank")
    @Size(max = 2000, message = "Description must not exceed 2000 characters")
    @Column(nullable = false, length = 2000)
    private String description;

    @Size(max = 100, message = "Tag must not exceed 100 characters")
    private String tag;

    @JsonIgnore  // never expose userId in API responses
    @Column(name = "user_id", nullable = false)
    private Long userId; // set by the service from JWT — client never sends this

    // constructors, getters, setters omitted for brevity
}

User Entity & Role Enum

The Role enum has three values. @Enumerated(EnumType.STRING) stores the name as text in the DB — safe to reorder the enum values later without corrupting existing rows.

User.java & Role.java
@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 50)
    private String username;

    @Column(nullable = false)
    private String password; // BCrypt hash — never plain text

    @Enumerated(EnumType.STRING) // stores "ADMIN"/"OPERATOR"/"GUEST", not 0/1/2
    @Column(nullable = false, length = 20)
    private Role role;
}

public enum Role {
    ADMIN,     // full access
    OPERATOR,  // read and write bookmarks
    GUEST      // read-only access
}

9. BookMarkService — Cache-Backed CRUD

Three read methods are each cached with their own key pattern. Any write clears the entire "bookmarks" cache with allEntries=true — simpler than tracking individual keys for a small user base.

🚨 SpEL + @Cacheable Requires Public Methods Spring Cache uses AOP proxies. SpEL expressions like #root.target.currentUserId() call the method via proxy reflection — private methods are invisible to the proxy, so the key evaluates to null and all users share one cache slot. Make currentUserId() public.
BookMarkService.java
@Service
public class BookMarkService {

    private final BookMarkRepo repository;

    public BookMarkService(BookMarkRepo repository) { this.repository = repository; }

    // Must be public — SpEL calls this via AOP proxy reflection
    public Long currentUserId() {
        AppUserDetails user = (AppUserDetails)
            SecurityContextHolder.getContext().getAuthentication().getPrincipal();
        return user.getId();
    }

    @Cacheable(value = "bookmarks", key = "'all:' + #root.target.currentUserId()")
    public List<BookMark> getAllBookMarks() {
        return repository.findByUserId(currentUserId());
    }

    @Cacheable(value = "bookmarks", key = "#title + ':' + #root.target.currentUserId()")
    public Optional<BookMark> getBookMark(String title) {
        return repository.findByTitleAndUserId(title, currentUserId());
    }

    @Cacheable(value = "bookmarks", key = "'tag:' + #tag + ':' + #root.target.currentUserId()")
    public List<BookMark> getBookMarksByTag(String tag) {
        return repository.findByUserIdAndTag(currentUserId(), tag);
    }

    @Transactional
    @CacheEvict(value = "bookmarks", allEntries = true)
    public BookMark createBookMark(BookMark bookMark) {
        Long userId = currentUserId();
        if (repository.existsByTitleAndUserId(bookMark.getTitle(), userId))
            throw new BookMarkExistException(bookMark.getTitle());
        bookMark.setUserId(userId); // always from JWT, client never sends this
        return repository.save(bookMark);
    }

    @Transactional
    @CacheEvict(value = "bookmarks", allEntries = true)
    public BookMark updateBookMark(String title, UpdateBookMarkRequest request) {
        BookMark bm = repository.findByTitleAndUserId(title, currentUserId())
            .orElseThrow(() -> new BookMarkNotFoundException(title));
        bm.setDescription(request.description());
        bm.setTag(request.tag());
        return repository.save(bm);
    }

    @Transactional
    @CacheEvict(value = "bookmarks", allEntries = true)
    public void deleteBookMark(String title) {
        if (!repository.existsByTitleAndUserId(title, currentUserId()))
            throw new BookMarkNotFoundException(title);
        repository.deleteByTitleAndUserId(title, currentUserId());
    }
}
💡 No Separate CacheConfig Class Caffeine is configured entirely through application.properties via spring.cache.caffeine.spec. No @Bean CacheManager needed — Spring Boot auto-configures it when Caffeine is on the classpath and spring.cache.type=caffeine is set.

10. GlobalExceptionHandler

Uses ResponseEntity (not @ResponseStatus) so each handler has full control over the response body and status code. A logger captures the error context for debugging without leaking internal details to the client.

GlobalExceptionHandler.java
@RestControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    @ExceptionHandler(BookMarkNotFoundException.class)
    public ResponseEntity<Map<String, String>> handleNotFound(BookMarkNotFoundException ex) {
        log.debug("Bookmark not found: {}", ex.getMessage());
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(Map.of("error", ex.getMessage()));
    }

    @ExceptionHandler(BookMarkExistException.class)
    public ResponseEntity<Map<String, String>> handleExist(BookMarkExistException ex) {
        log.debug("Bookmark conflict: {}", ex.getMessage());
        return ResponseEntity.status(HttpStatus.CONFLICT)
            .body(Map.of("error", ex.getMessage()));
    }

    // Returns { "fieldName": "message" } for each failed @Valid constraint
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> handleValidation(MethodArgumentNotValidException ex) {
        Map<String, String> errors = ex.getBindingResult().getFieldErrors().stream()
            .collect(Collectors.toMap(fe -> fe.getField(), fe -> fe.getDefaultMessage()));
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(errors);
    }

    // Spring MVC 6.2+ replaced NoHandlerFoundException with NoResourceFoundException
    @ExceptionHandler(NoResourceFoundException.class)
    public ResponseEntity<Map<String, String>> handleNoResource(NoResourceFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(Map.of("error", "Resource not found"));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, String>> handleGeneric(Exception ex) {
        log.error("Unhandled exception", ex);
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(Map.of("error", "An unexpected error occurred"));
    }
}

11. RateLimitFilter — Bucket4j

Rate limiting runs as a top-level servlet filter — it applies to every path including /login. Capacity and refill rate are read from application.properties via @Value so they can be tuned without recompiling. Static asset paths are skipped because Swagger UI loads several files per page load.

RateLimitFilter.java
@Component  // intentionally global — applies to every path including /login
public class RateLimitFilter extends OncePerRequestFilter {

    @Value("${app.rate-limit.capacity}")
    private int capacity;

    @Value("${app.rate-limit.refill-per-minute}")
    private int refillPerMinute;

    private final Map<String, Bucket> buckets = new ConcurrentHashMap<>();

    private Bucket newBucket() {
        Bandwidth limit = Bandwidth.builder()
            .capacity(capacity)
            .refillGreedy(refillPerMinute, Duration.ofMinutes(1))
            .build();
        return Bucket.builder().addLimit(limit).build();
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                        HttpServletResponse response,
                                        FilterChain filterChain)
            throws ServletException, IOException {

        String uri = request.getRequestURI();
        // Skip static assets — Swagger UI loads ~7 files per page
        if (uri.startsWith("/swagger-ui/") || uri.startsWith("/webjars/")
                || uri.startsWith("/v3/api-docs")) {
            filterChain.doFilter(request, response);
            return;
        }

        String ip     = request.getRemoteAddr();
        Bucket bucket = buckets.computeIfAbsent(ip, k -> newBucket());

        if (bucket.tryConsume(1)) {
            filterChain.doFilter(request, response);
        } else {
            response.setStatus(HttpStatus.TOO_MANY_REQUESTS.value()); // 429
            response.setContentType(MediaType.APPLICATION_JSON_VALUE);
            response.getWriter().write(
                "{\"error\": \"Too many requests. Limit is " + refillPerMinute + " requests per minute.\"}");
        }
    }
}

12. FlywayConfig & SQL Migration

⚠ Spring Boot 4.x Flyway Silent-Skip Bug With flyway-database-postgresql on the classpath, Spring Boot 4.x's FlywayAutoConfiguration can silently skip migration with no error. The fix: set spring.flyway.enabled=false to opt out of auto-config, then declare an explicit bean with @Bean(initMethod="migrate"). This guarantees Flyway runs before Hibernate validates the schema.
FlywayConfig.java
@Configuration
public class FlywayConfig {

    @Bean(initMethod = "migrate")
    public Flyway flyway(DataSource dataSource) {
        return Flyway.configure()
            .dataSource(dataSource)
            .locations("classpath:db/migration")
            .load();
    }
}

A single migration creates both tables. The bookmark table uses a composite primary key (title, user_id) — same title is allowed across different users. The role column has a CHECK constraint matching the enum values.

db/migration/V1__init.sql
CREATE TABLE IF NOT EXISTS users (
    id       BIGSERIAL    PRIMARY KEY,
    username VARCHAR(50)  NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,               -- BCrypt hash, never plain text
    role     VARCHAR(20)  NOT NULL
        CHECK (role IN ('ADMIN', 'OPERATOR', 'GUEST'))
);

CREATE TABLE IF NOT EXISTS bookmarks (
    title       VARCHAR(255)  NOT NULL,
    description VARCHAR(2000) NOT NULL,
    tag         VARCHAR(100),
    user_id     BIGINT        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    PRIMARY KEY (title, user_id)  -- composite: same title allowed across different users
);

    }

    @PostMapping
    public ResponseEntity<BookMark> createBookMark(@Valid @RequestBody BookMark bookMark) {
        return ResponseEntity.status(HttpStatus.CREATED).body(service.createBookMark(bookMark));
    }

    // title from path; only description + tag in body
    @PutMapping("/{title}")
    public ResponseEntity<BookMark> updateBookMark(@PathVariable String title,
                                                      @Valid @RequestBody UpdateBookMarkRequest req) {
        return ResponseEntity.ok(service.updateBookMark(title, req));
    }

    @DeleteMapping("/{title}")
    public ResponseEntity<Void> deleteBookMark(@PathVariable String title) {
        service.deleteBookMark(title);
        return ResponseEntity.noContent().build();
    }
}

AuthController — Token Page

After a browser login, Spring Security redirects to /auth/token. AuthController generates a fresh JWT and passes it to the token.html Thymeleaf template. The user copies the token and shares it with their AI agent. There is no API login endpoint — all authentication is browser-session-based.

AuthController.java
@Controller
@RequestMapping("/auth")
public class AuthController {

    private final JwtUtil jwtUtil;

    public AuthController(JwtUtil jwtUtil) { this.jwtUtil = jwtUtil; }

    // Session-protected — only reachable after /login.
    // Generates a JWT for the logged-in user and renders it on the token page.
    // User copies the token and gives it to their AI agent.
    @GetMapping("/token")
    public String getToken(Authentication authentication, Model model) {
        AppUserDetails userDetails = (AppUserDetails) authentication.getPrincipal();
        String token = jwtUtil.generate(
            userDetails.getId(), userDetails.getUsername(), userDetails.getRole());
        model.addAttribute("username", userDetails.getUsername());
        model.addAttribute("token", token);
        return "token"; // → templates/token.html
    }
}

// RootController — / → /auth/token (Security intercepts and redirects to /login if not logged in)
@RestController
public class RootController {
    @GetMapping("/")
    public RedirectView root() { return new RedirectView("/auth/token"); }
}

15. Dockerfile & docker-compose.yml

Multi-stage build: JDK image compiles the JAR, JRE Alpine image runs it. The log directory is created in the Dockerfile; docker-compose mounts it as a named volume so logs survive container restarts. JVM memory is capped in docker-compose.yml via JAVA_TOOL_OPTIONS, not in the Dockerfile — so it can be changed without rebuilding the image.

Dockerfile
# ── Stage 1: Build ───────────────────────────────────────────────────
FROM eclipse-temurin:25-jdk-alpine AS build
WORKDIR /app

# Copy dependency declarations first — Docker caches this layer.
# Dependencies are only re-downloaded when build.gradle.kts changes.
COPY gradlew ./
COPY gradle/ gradle/
COPY build.gradle.kts settings.gradle.kts ./
RUN chmod +x gradlew && ./gradlew dependencies --no-daemon

COPY src/ src/
RUN ./gradlew bootJar --no-daemon

# ── Stage 2: Run ─────────────────────────────────────────────────────
FROM eclipse-temurin:25-jre-alpine
WORKDIR /app

# Log directory — docker-compose mounts a named volume here
RUN mkdir -p /var/log/memento

COPY --from=build /app/build/libs/*.jar app.jar

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

16. GitHub Actions CI/CD

Java and Gradle run inside Docker on CI — no setup-java step needed. The compose file is synced to the VPS with scp-action before each deploy so the VPS always runs the latest version. docker image prune keeps disk usage in check.

.github/workflows/deploy.yml
name: Build and Deploy

on:
  push:
    branches: [main]

env:
  IMAGE: ghcr.io/${{ github.repository }}

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write   # required to push to ghcr.io

    steps:
      - uses: actions/checkout@v4

      # GITHUB_TOKEN is auto-generated — no extra secret needed
      - name: Log in to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      # Java + Gradle run inside Docker — no setup-java step needed
      - name: Build and push Docker image
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ${{ env.IMAGE }}:latest

      # Keep docker-compose.yml on VPS in sync with the repo
      - name: Sync docker-compose.yml to VPS
        uses: appleboy/scp-action@v0.1.7
        with:
          host:     ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key:      ${{ secrets.VPS_SSH_KEY }}
          source:   docker-compose.yml
          target:   /opt/memento/

      - name: Deploy on VPS
        uses: appleboy/ssh-action@v1
        with:
          host:     ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key:      ${{ secrets.VPS_SSH_KEY }}
          script: |
            set -e
            cd /opt/memento
            grep -q "^APP_IMAGE=" .env || { echo "ERROR: APP_IMAGE not in .env"; exit 1; }
            docker compose pull app
            docker compose up -d app
            docker image prune -f
ℹ Required Secrets Add VPS_HOST, VPS_USER, and VPS_SSH_KEY under repo → Settings → Secrets → Actions. GITHUB_TOKEN is provided automatically. On the VPS, create /opt/memento/.env with APP_IMAGE, SPRING_DATASOURCE_USERNAME, SPRING_DATASOURCE_PASSWORD, and JWT_SECRET.

17. Known Gotchas

GotchaSymptomRoot CauseFix
@Component filter double-runs JWT filter executes twice; runs on /login etc. Spring Boot registers @Component filters globally AND Security adds them to the chain FilterRegistrationBean(enabled=false) in SecurityConfig
MVC matcher fails on static paths IllegalArgumentException for /webjars/** inside a filter chain Security 7.x MVC matchers require a @Controller mapping — static assets have none WebSecurityCustomizer.ignoring() to bypass chains entirely
Flyway silently skips migration App starts, tables missing, JPA EntityNotFoundException on first query Spring Boot 4.x FlywayAutoConfiguration skips migration with flyway-database-postgresql on classpath spring.flyway.enabled=false + explicit @Bean(initMethod="migrate")
@Cacheable SpEL key is null All users share one cache entry; wrong data returned AOP proxy can't reach private methods — key evaluates to null Make currentUserId() public
JJWT 0.12.x API change NoSuchMethodError calling parserBuilder() or parseClaimsJws() JJWT 0.12.x replaced the entire builder/parser API from 0.11.x Use Jwts.parser().verifyWith(key).build().parseSignedClaims(token)
NoResourceFoundException unhandled Missing paths return Spring's HTML error page instead of JSON Spring MVC 6.2+ replaced NoHandlerFoundException with NoResourceFoundException Add @ExceptionHandler(NoResourceFoundException.class) in @RestControllerAdvice
Logout breaks with AntPathRequestMatcher ClassNotFoundException or NoSuchMethodError at startup AntPathRequestMatcher was removed in Spring Security 7.x Use a lambda: .logoutRequestMatcher(req -> "GET".equals(req.getMethod()) && "/logout".equals(req.getRequestURI()))

18. Full Request Flow

API Request (AI Agent)

1
Agent sends GET /api/bookmarks with Authorization: Bearer <token> to port 8080
2
RateLimitFilter — checks per-IP bucket; returns 429 JSON if exhausted
3
WebSecurityCustomizer — path is /api/**, not a static path, so filter chains run
4
SecurityFilterChain @Order(1) — claims /api/** via securityMatcher
5
JwtAuthFilter — calls jwtUtil.isValid(token) → parse(token) → loads UserDetails → sets SecurityContext
6
BookMarkController.getAllBookMarks() is invoked
7
BookMarkService — @Cacheable intercepts; returns cached list or queries BookMarkRepo
8
JSON response returned; @JsonIgnore on userId means it never appears in the output

Browser Request (Login → Token)

1
User opens browser → GET / → RootController redirects to /auth/token
2
No session → Security redirects to /login → LoginController renders login.html
3
User submits form → POST /login handled by Spring Security's UsernamePasswordAuthenticationFilter
4
CustomUserDetailsService.loadUserByUsername() → loads user → BCrypt password check → session created
5
Redirect to /auth/token → AuthController.getToken() generates JWT → renders token.html
6
User copies JWT → pastes into AI agent → agent uses it for all subsequent API calls
